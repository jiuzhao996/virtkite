## 1. 项目结构

目录树：`main.go / config / database / handler / middleware / model / service/virt / service/tasks / service/console / service/vnc / web / static / docs`。

分层说明：handler 直连 GORM；虚拟化操作下沉至 `service/virt` 封装层（go-libvirt 直连 `qemu:///system`）；耗时操作委托 `service/tasks` 后台执行；控制台连接由 `service/console` 注册表跟踪。所有 libvirt 调用走 `service/virt`，错误用 `%w` 包装并注明 virsh 等价命令。

## 2. 认证与授权模块（含 RBAC 只读角色）

- 登录流程：bcrypt 校验 + JWT 签发（`handler/auth.go`，`middleware.GenerateToken`）。
- JWT 中间件：`AuthMiddleware`（`middleware/jwt.go`），支持 `Authorization` 头与 WS `?token=` 查询参数；校验用户存在与 `is_active`。
- 角色中间件：`AdminMiddleware`（仅 `admin`）与 `OperatorMiddleware`（RBAC 第一阶段：只读 viewer）。
  - 关键函数：`middleware/jwt.go` 的 `OperatorMiddleware()`、`isVNCTokenPath()`。
  - 规则：admin 放行全部；viewer 放行全部 GET 与 `POST /api/vms/:id/vnc-token`（图形控制台查看），其余 POST/PUT/DELETE 一律 403。
  - 路由装配（`main.go`）：`/users`、`/audit`、`/settings` 用 `AdminMiddleware`；`/hosts`、`/vms`、`/storage`、`/networks`、`/images`、`/dashboard`、`/tasks`、`/sessions` 用 `OperatorMiddleware`。
- 角色×资源×读写矩阵：

| 资源组 | GET（读） | POST/PUT/DELETE（写） |
|---|---|---|
| `/hosts`、`/vms`、`/storage`、`/networks`、`/images`、`/dashboard`、`/tasks`、`/sessions` | admin ✓ / viewer ✓ | admin ✓ / viewer ✗（403） |
| `POST /api/vms/:id/vnc-token` | —（viewer ✓，图形查看） | viewer ✓（仅此例外） |
| `/users`、`/audit`、`/settings` | admin ✓ / viewer ✗ | admin ✓ / viewer ✗ |
| 前端路由 | `vms/new`、`settings`、`audit` 标 `requiresAdmin`，viewer 直输 URL 重定向 dashboard（`web/src/router/index.js`） | — |

## 3. 宿主机管理模块

- CRUD 接口实现。
- 连通性测试、实时状态采集（hostname/free/uname）。
- 关键代码要点：`handler/host.go`。

## 4. 虚拟机生命周期模块（核心）

- 列表/详情（go-libvirt 状态同步：ListAllDomains + DomainGetState）。
- 创建：生成 UUID/MAC → DB 写入 → **存储池建卷（StorageVolCreateXML，qcow2）** → DomainDefineXML → 失败回滚。当前创建/删除/克隆/优雅关机已转异步任务（见 6.5），同步语义保留在 executor 内。
- 启停/重启/删除（DomainCreate / Shutdown+Destroy / Reboot / Undefine+存储卷删除）。
- 建盘走 libvirt 存储池/卷 API（对应 virsh vol-create-as），支持多存储池选择（默认 vmops）。
- 停止策略：优雅关机 + 轮询（15s）超时强制断电（已搬入 `execStopVM` 后台执行，根治 axios 超时）。
- 删除策略：运行中先 Destroy 再 Undefine，再删存储卷；删除前先取完整磁盘清单再删定义，仅删平台托管池路径下卷，避免误删共享基镜像。
- domain XML 模板、名称校验、随机 MAC/UUID。
- 存量 VM 导入/纳管：扫描 libvirt 全部域（ListDomainsWithDetail，解析 XML 取 vCPU/内存/MAC/磁盘路径），与 DB UUID 比对筛出未纳管域，勾选导入只写 DB、不改 libvirt；磁盘归属按存储池路径前缀推断。
- 关键代码要点：`handler/vm.go`、`service/virt/domain.go`、`service/virt/storage.go`、`service/virt/import.go`、`service/tasks/vm_tasks.go`。

## 5. 镜像管理模块

## 6.3 网页控制台模块（noVNC + Web 终端 + 串口）

- 后端：VM VNC 端口解析（DomainGetXMLDesc graphics port，对应 `virsh dumpxml`）+ token 生成（`VNCHandler.RequestToken`，`POST /api/vms/:id/vnc-token`）。
- websockify：JSONTokenApi 动态解析 token → host:port（`VNCHandler.ResolveToken`，`GET /api/vnc/token/:token`，解析即经 `TouchByToken` 刷新会话存活）。
- Web 终端：WebSocket→SSH 桥（x/crypto/ssh），首个消息携带连接参数，xterm.js 前端（`handler/terminal.go` 的 `Connect`，`GET /api/vms/:id/terminal`）。
- 串口 Console：libvirt `DomainOpenConsoleBidirectional`（`service/virt/console.go`），禁止直接打开 `/dev/pts/*`；`GET /api/vms/:id/serial`。
- 前端：VM 列表「控制台」→ 站内选择页（图形控制台 noVNC 内嵌 / Web 终端 SSH / 串口）。
- 会话收敛：三链路建会话记录，SSH/串口可强制断开，VNC 靠过期清扫收敛（详见 6.6）。
- 关键代码要点：`service/vnc/token.go`（`TokenStore/Generate/Lookup`）、`handler/vnc.go`、`handler/terminal.go`、`web/src/views/ConsolePage.vue`。

- 关键代码要点：`service/virt/snapshot.go`（`CreateSnapshot/ListSnapshots`）。

## 6.5 异步任务子系统

设计思路：同步 `StopVM` 轮询 15s 会撞上 axios 超时，大盘创建/克隆同样慢。参考 JumpServer/PVE 的 task 队列语义，将五个耗时操作后台化：handler 只做基础参数校验后 `Submit` 入库并返回 `202 + {task_id}`，固定 worker 池执行并回写进度，前端 `pollTask` 轮询至终态。

关键接口与函数（均与代码逐字一致）：

| 层次 | 函数/接口 | 说明 |
|---|---|---|
| 模型 | `model.Task`（表 `tasks`） | `type/title/status/progress/payload/result/error/user_id/username/vm_id/vm_name` |
| 队列 | `tasks.NewManager(db)`（`service/tasks/manager.go`） | 内部 `virt.New()`，起 4 个 worker goroutine（`workerCount=4`，`queueBufferSize=128`） |
| 队列 | `Manager.Register(taskType, fn)` | 启动时注册 executor |
| 队列 | `Manager.Submit(taskType, title, payload, userID, username, vmName, vmID)` | 序列化 payload、置 `pending` 入库、非阻塞入队（满则另起 goroutine） |
| 队列 | `Manager.Get(id)` / `Manager.List(limit, status)` | 单查 / 按 id 倒序（默认 50、上限 200） |
| 执行 | `ExecContext`（`DB/Virt/Task/Payload/Report`）、`Executor`、`ProgressFunc` | executor  cấm 引用 gin/handler，错误用中文 `%w` 包装 |
| 执行 | `RegisterVMTasks(m)`（`service/tasks/vm_tasks.go`） | 注册 `create_vm / delete_vm / clone_vm / clone_image_vm / stop_vm` |
| 执行 | `execCreateVM` | 搬运自 `CreateVM`：校验名称→查宿主→默认值→UUID/MAC→逐盘落地（Report 10/30/50/70）→seed→`BuildDomainXML`→写 DB→`DefineDomain`；成功回填 `Result={"vm_id"}`；失败清理已建卷与 seed |
| 执行 | `execDeleteVM` | 搬运自 `DeleteVM`：取磁盘清单→`UndefineDomain`→逐卷清理+seed→软删除；对应 `virsh undefine + vol-delete` |
| 执行 | `execCloneVM` | 搬运自 `CloneVM`：`GetDomainSpec`→覆盖→`CloneVMFromSpec`→查新 UUID/MAC→写 DB；对应 `virsh vol-clone + define` |
| 执行 | `execCloneImageVM` | 搬运自镜像 `CloneVM`：`LookupVolByPath`→`CloneVolumeFromVol`→seed→define→DB；云镜像 linked clone |
| 执行 | `execStopVM` | 搬运自 `StopVM`：`ShutdownDomain`→15s 轮询（每秒 Report）→超时 `DestroyDomain`→DB 置 `shut off`；对应 `virsh shutdown / destroy` |
| REST | `POST /api/vms`、`DELETE /api/vms/:id`、`POST /api/vms/:id/clone`、`POST /api/images/:id/clone`、`POST /api/vms/:id/stop` | 改异步，202 返回 `{task_id}` |
| REST | `TaskHandler.ListTasks/GetTask/DeleteTask`（`handler/task.go`） | `GET /api/tasks?status=&limit=` 返回 `{total, items}`；`GET /api/tasks/:id`；`DELETE /api/tasks/:id` 仅终态可删 |
| 前端 | `web/src/utils/task.js`（`pollTask`）、`TaskList.vue` | `pollTask(taskId, {interval=2000, timeout=300000})` 轮询至 success resolve / failed reject；任务中心智能轮询（有进行中才刷）+ 清理已完成 |

virsh 等价：创建 `vol-create-as + define`；删除 `undefine + vol-delete`；克隆 `vol-clone + define`；停止 `shutdown（超时 destroy）`。

## 6.6 会话管理（控制台会话跟踪）

设计思路：VNC 走 websockify 中转、后端看不到断开事件，只能靠 token 解析事件刷新存活 + 过期清扫收敛；SSH/串口走后端 WS 桥，连接持有在内存注册表、可服务端强制断开。三链路统一埋点写 `console_sessions`，做到“谁连了哪台 VM”可查、可断、可收敛。

关键接口与函数：

| 层次 | 函数/接口 | 说明 |
|---|---|---|
| 注册表 | `console.NewRegistry(db)`（`service/console/registry.go`） | 内存 `conns`（sessionID→WS，仅 ssh/serial）+ `byToken`（vnc token→sessionID）+ DB 持久 |
| 注册表 | `Registry.Open(...)` | SSH/串口 WS 建会话并持有连接 |
| 注册表 | `Registry.OpenVNC(...)` | VNC 建会话并建 token 映射 |
| 注册表 | `Registry.TouchByToken(token)` | websockify 解析时刷新 `last_seen` |
| 注册表 | `Registry.Close(id)` | 幂等关闭并释放资源 |
| 注册表 | `Registry.Disconnect(id)` | 关闭 WS（先发关闭帧）；VNC 无可控连接返回 `ErrNoLiveConn` |
| 注册表 | `Registry.StartSweeper()` | 每 5 分钟将超 60 分钟（`vncStaleAfter`）无解析的 active VNC 会话标 `closed` |
| 埋点 | `VNCHandler.RequestToken`（`POST /api/vms/:id/vnc-token`） | 签发 token 时 `OpenVNC` |
| 埋点 | `VNCHandler.ResolveToken`（`GET /api/vnc/token/:token`） | 解析时 `TouchByToken` |
| 埋点 | WS 终端连接处理（`GET /api/vms/:id/terminal`） | 建连成功后以 `ssh` 类型 `Open`，断开时 `Close` |
| 埋点 | 串口连接处理（`GET /api/vms/:id/serial`） | 以 `serial` 类型 `Open`，断开时 `Close` |
| REST | `SessionHandler.ListSessions`（`handler/session.go`） | `GET /api/sessions`，进行中优先、开始时间倒序，默认 100 条 |
| REST | `SessionHandler.DisconnectSession` | `POST /api/sessions/:id/disconnect`；VNC 返回“中转连接无法强制断开”提示 |
| 前端 | `web/src/views/SessionList.vue` | 会话列表轮询 + 强制断开（VNC 行禁用并提示） |

## 6.7 linked clone（增量克隆）

设计思路：PVE 式 linked clone。子卷经 `StorageVolCreateXMLFrom` 以父卷为 backing 创建，qcow2 写时复制，子卷初始仅占元数据量级空间；子卷存续期间父卷不可删。VM 克隆与镜像建机共用该原语。

关键函数（`service/virt/clone.go`，均与代码逐字一致）：

| 函数 | 说明（virsh 等价） |
|---|---|
| `CloneVolumeFromVol(poolName, srcVolName, newVolName)` | 查池→查父卷→取父卷虚拟容量→`StorageVolCreateXMLFrom` 建子卷→返回子卷路径；对应 `virsh vol-clone` |
| `LookupVolByPath(volPath)` | 按路径反查池名与卷名（含直接落盘文件的 refresh 后反查）；对应 `virsh vol-key + pool-name` |
| `CloneVMFromSpec(source *DomainSpec, newName)` | 取源首个 `device==disk` 系统盘 linked clone→替换 source→重生成 UUID→`BuildDomainXML`→`DomainDefineXML`；对应 `virsh vol-clone + virsh define` |

调用链：`execCloneVM`（`POST /api/vms/:id/clone`，基于源 VM）、`execCloneImageVM`（`POST /api/images/:id/clone`，基于模板/云镜像，`newDiskName=name+"-sys"`）。删除 VM 时仅删托管池路径下卷，避免误删被引用的父盘/共享基镜像。

## 6.8 cloud-init seed

设计思路：创建 VM 时可选注入主机名、用户口令、SSH 公钥与静态网络。纯 Go 生成 iso9660 seed ISO（卷标 `cidata`，cloud-init 约定），落到独立 seed 目录（`SEED_DIR`，默认 `/home/jiuzhao/vmops/data/seed`，web 可写、qemu 可读，不依赖存储池目录权限），以只读 cdrom 挂载，引导顺序提至光驱优先。

关键函数（`service/virt/cloudinit.go`）：`GenerateSeedISO(cfg *CloudInitSpec)`，根目录含 `user-data / meta-data / network-config` 三文件：`meta-data` 写 `instance-id: vmops-<hostname>` 与 `local-hostname`；`user-data` 写 `#cloud-config` + 用户口令/ssh key/hostname；`network-config` 在 static 时写 v1 格式、缺省 dhcp。调用方：`execCreateVM` / `execCloneImageVM`（缺 hostname 时默认 VM 名），seed 文件名为 `<vm名>-seed.iso`，删除 VM 时一并清理。

## 6.9 硬件热管理（磁盘/网卡/核/内存）

设计思路：结构化 `DomainSpec`（`service/virt/spec.go`）作为 dumpxml 的解析与重建模型；运行中设备变更用 `LIVE|CONFIG` 热插拔并落配置，停机仅落配置；核/内存预留热升级头寸（`vcpuMax/memoryMaxKiB`），运行中可在上限内热调。

关键函数：

| 函数 | 说明（virsh 等价） |
|---|---|
| `GetDomainSpec(name)` | `dumpxml` 解析 + `DomainGetAutostart` 回填，返回 `{vm, spec}`（`spec` 含 `raw_xml`）；对应 `virsh dumpxml + dominfo` |
| `ParseDomainXML(xml)` / `BuildDomainXML(spec)` | 纯函数：解析↔生成，含 graphics/features/acpi、引导顺序、磁盘网卡 |
| `NextDiskTarget(spec, bus)` | 按 bus 自动分配 `vda/sda/hda` 序号 |
| `AttachDisk(domain, d)` / `DetachDisk(domain, target)` | 对应 `virsh attach-device / detach-device` |
| `AttachInterface(domain, i)` / `DetachInterface(domain, mac)` | 对应 `virsh attach-interface / detach-interface`（移除按 MAC 匹配，需带 source 拼装） |
| `SetVcpus(domain, n)` | 对应 `virsh setvcpus`（运行中热增受上限限制，热减需关机） |
| `SetMemory(domain, mb)` | 对应 `virsh setmem`（运行中增大不能超开机时大小，超出请关机调整） |
| `PauseDomain/ResumeDomain`（`domain2.go`） | 对应 `virsh suspend / resume` |
| `SetAutostart/GetAutostart` | 对应 `virsh autostart` |

REST（`main.go`，见 api-contract）：`GET/PUT /api/vms/:id/spec`、`POST /:id/pause|resume`、`POST/DELETE /:id/devices/disks[/:target]`、`POST/DELETE /:id/devices/interfaces[/:mac]`、`PUT /:id/cpu|memory|autostart|boot`、`GET /:id/stats`。前端 `VmDetail.vue` 按配置/性能/核/内存/磁盘/网卡/快照分栏展示，性能 2s 轮询。

## 7.1 Prometheus 监控（内建 exporter）

设计思路：不另起 exporter 进程，后端内建 Prometheus exposition（`service/metrics` + `GET /metrics` 公开路由，供 Prometheus 15s scrape；生产环境建议防火墙限制来源）。抓取前刷新快照指标，失败项保留旧值。

指标（label 仅 VM 名/池名等有界值）：

| 指标 | 类型 | 说明 |
|---|---|---|
| `vmops_vm_cpu_percent{vm}` | Gauge | VM CPU%（服务端差分） |
| `vmops_vm_mem_used/total_kib{vm}` | Gauge | VM 内存（balloon 优先） |
| `vmops_vm_disk_read/write_bps{vm}` | Gauge | 首盘 IO |
| `vmops_vm_net_rx/tx_bps{vm}` | Gauge | 首网卡 IO |
| `vmops_vm_running{vm}` | Gauge | 运行 1/0 |
| `vmops_host_cpu_percent/mem_*` | Gauge | 宿主机（/proc 差分） |
| `vmops_pool_capacity/available_bytes{pool}` | Gauge | 存储池 |
| `vmops_tasks_pending/running` | Gauge | 任务队列深度 |
| `go_*/process_*` | Gauge | Go 运行时（client 自带） |

关键文件：`service/metrics/metrics.go`（Collector.Update + stale 序列清理）、`handler/metrics.go`、`deploy/prometheus.yml`、`deploy/alerts.yml`（VM 归零/Host CPU/池空间/任务堆积/单 VM 过热 5 条规则）、`deploy/grafana-dashboard.json`（9 面板）、`docker-compose.yml`（prometheus:9090 + grafana:3000，libvirt socket 直通 app 容器）。

## 8. 前端实现

- 工程结构（web/src：api/store/router/layout/views/utils）。
- 页面：Login/Dashboard/VmList/VmDetail/HostList/ImageList/StorageList/NetworkList/AuditList/TaskList/SessionList/Settings/CreateVmWizard/ConsolePage。
- 与后端联调（axios 拦截器、token 管理、统一响应解包）。
