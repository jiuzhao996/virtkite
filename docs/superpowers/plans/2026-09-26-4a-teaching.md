# 4A 教学闭环三功能 + 两收口 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans（Native）。Steps 用 checkbox。

**Goal:** 用户组授权、授权申请+审批流、jumpd 命令黑名单三功能落地，砍除 XML 直定义路由与 Loki/Promtail 容器，答辩主线「申请→审批→限时授权→任意终端→审计→危险命令拦截」全链自研。

**Architecture:** 组授权 = 新表 user_groups/user_group_members/vm_group_grants，可见性 helper 在 handler/vm_grant.go 内做并集；申请流 = 新表 grant_requests + 审批通过即写 vm_grants（限时）；黑名单 = settings 键 + forwardKeys 行缓冲匹配（逐字节透传不破坏全屏程序，\r 行判定拦截）+ audit_logs 落行。

**Tech Stack:** 现有 GORM/gin/Element Plus，零新依赖。

## Global Constraints

1. 授权判定「未过期」口径与 handler/vm_grant.go 逐字一致；admin 豁免不变。
2. operator 写权限仅 /api/vms 前缀（OperatorMiddleware）——申请端点必须挂 /api/vms/:id/grant-request，审批端点挂 /api/grant-requests（AdminMiddleware）。
3. 状态字面量用常量；错误 %w 中文；goroutine recover；`_ =` 禁止（dbx 例外）。
4. 黑名单逐字节透传为默认，仅整行 \r 判定拦截（保护 vim/htop 交互）；黑名单可配置（settings 键 jumpd_cmd_blacklist，默认 rm -rf,mkfs,dd if=,shred,:(){）。
5. METRICS_TOKEN 取 deploy/prometheus.yml vmops job 已在发送的 credentials 值（ba39de…），prometheus.yml 零改动。
6. 前端改动最小化：组管理并入 UserList tab；组授权并入 VmDetail 授权面板；申请独立页 GrantRequests.vue（资源组，operateOnly）。
