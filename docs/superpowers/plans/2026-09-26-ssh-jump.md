# SSH 跳板入口（jumpd）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户 `ssh <用户名>@<宿主机> -p 2222`，经平台密码认证后从交互式菜单选择被授权的运行中虚拟机，直达其 SSH 终端，会话落 console_sessions 审计。

**Architecture:** 新包 `service/jumpd` 内置 SSH 服务端（`golang.org/x/crypto/ssh`），认证复用 users 表 bcrypt 校验，资产菜单复用 VM 资产授权体系（vm_grants），连接桥经既有 `vmssh.NewOptions`/`vmssh.Dial` 封装（白名单 + TOFU 主机密钥复用不绕行），双向 io.Copy 桥接用户终端与 VM 的 SSH 会话。`main.go` 里 goroutine 启动，env 开关默认关闭，前端零改动。

**Tech Stack:** golang.org/x/crypto/ssh（go.mod:11 已有 v0.54.0）、GORM（现有）、vmssh 封装（现有）、dbx（现有，会话收口）、secretbox（现有，凭据解密）

**Spec:** 本文档「功能定义」节。

---

## 功能定义

1. **入口**：vmops 进程内起 SSH 服务端，监听 `JUMPD_PORT`（默认 2222），`JUMPD_ENABLED=1` 才启动（默认关）。
2. **认证**：对 `users` 表按用户名查询 + bcrypt 校验（`middleware.CheckPassword`），逻辑与 `handler/auth.go` Login 一致（含 `IsActive` 检查）。**viewer 角色直接拒绝**（提示「只读角色不支持终端登录」）。per-IP 失败限流：同 IP 1 分钟内失败 5 次锁定（与 `handler/auth.go` loginLimiter 同策略），限流器为包内小对象、可单测。
3. **资产菜单**：认证通过后在终端展示交互式菜单，**只列同时满足**以下条件的虚拟机：
   - 该用户持有效授权（`vm_grants`，「未过期」判定与现有查询逐字一致，见 Global Constraints 第 4 条）；admin 不受授权约束全量可见；
   - `status = model.VMStatusRunning`（"running"）；
   - `vms.ip` 非空（DHCP/QGA 回填，见 handler/vm_ip_sync.go）；
   - 已托管 SSH 凭据（`vm_credentials` 有该 VM 行）——**这是对 spec 第 4 条的落点澄清，见下方「关键事实澄清」**。
   菜单纯键盘操作：数字 `1-9` 选择，`j` 翻下一页（末页回首页，即「上下分页」仅靠 j/q 可达），`q` 断开退出；每页 9 台；菜单列出「编号. 名称 (IP)」。
4. **连接桥**：选中后服务端解密该 VM 的托管凭据 → `vmssh.NewOptions(vm.IP, vm.IP, cred.Port, cred.User, 明文口令)` → `vmssh.Dial` → `client.NewSession()` + `RequestPty`（回放用户侧 PTY 请求的 term/宽高，支持 window-change）+ `Shell()` → 两条 goroutine `io.Copy` 双向桥接，均带 `defer recover()`。
5. **会话与审计**：桥建立时直接写 `console_sessions` 一行（`type="jump"`，先例 `Registry.OpenVNC` 直接 Create）；桥断开时经 `dbx.PersistBestEffort` 置 `closed` + `ended_at`（先例 `Registry.Close`）。不做 HTTP 审计中间件复用；过程用结构化日志（`log.Printf("[jumpd] ...")`）。
6. **跳板自身 host key**：ed25519，首次生成后持久化 `data/jumpd_host_key`（0600，该目录已 gitignore），损坏即 fail-closed 拒绝启动，客户端 known_hosts 才能稳定。

### 关键事实澄清（凭据来源，必须读）

spec 第 4 条问「vms 表是否存 ssh_port/ssh_user 字段？没有就用 root/22」——**核实结论：`model/vm.go` 的 vms 表没有这两个字段，且没有任何口令来源可用 root/22 直接连**（`vmssh.Dial` 必须密码认证）。但项目已有 VM SSH 凭据托管体系：`model/vm_credential.go:12` 的 `VMCredential{VMID(唯一), User, Port(默认22), PasswordEnc(AES-256-GCM), Salt}`，Web 端文件管理/应用商店的 use_saved 通道就在用它。因此本计划：

- **连接凭据一律取该 VM 已托管的 `vm_credentials` 行**，解密用 `secretbox.OpenWithMaster(masterSecret, cred.Salt, cred.PasswordEnc)`（与 `service/tasks/app_tasks.go:175` 同款）；masterSecret 由 `main.go` 以 `handler.CredentialMasterSecret()` 注入（与 `main.go:169` 给 `tasks.RegisterAppTasks` 注入同源同款）。
- **未托管凭据的 VM 不进菜单**（fail-closed：不可达的选项比选了再报错的选项好），菜单提示用户先在 Web 凭据面板保存。
- 明文口令只在内存流转：不进日志、不落库、不回显——错误日志一律不含密码（硬性禁止第 2 条）。

## Global Constraints

1. 新代码全部在 `service/jumpd` 包（接线点 main.go/config/handler 两处小改除外）；libvirt/SSH 出口一律走既有封装：目标拨号只用 `vmssh.NewOptions` + `vmssh.Dial`，禁止自行组装 `ssh.ClientConfig` 或直接 `ssh.Dial`（jumpd 自身作为 SSH **服务端**的 `ssh.NewServerConn` 不受此限）。
2. 错误包装一律 `fmt.Errorf("中文描述: %w", err)`；注释中文并写清动机；用户可见文案（菜单/拒绝提示）中文。
3. 所有自起 goroutine（SSH 服务端 accept 循环、桥接 io.Copy×2、main.go 启动 goroutine）必须 `defer recover()`，panic 值与 `debug.Stack()` 只进 `log.Printf`。
4. 授权「未过期」判定必须与现有代码逐字一致：DB 条件 `Where("expires_at IS NULL OR expires_at > ?", time.Now())`（handler/vm_grant.go:32/:45 原文），纯函数口径 `expiresAt == nil || expiresAt.After(now)`（handler/vm_grant.go:14 原文）；admin 全量可见、其余按授权集合，语义同 `vmVisible`/`grantedVMIDs`。
5. 状态字面量只用常量：`model.VMStatusRunning`；会话状态 "active"/"closed" 与 type "jump" 按 `model/session.go` 现有取值风格。
6. 写库失败禁止 `_ =`：会话关闭走 `dbx.PersistBestEffort`（幂等等值更新，符合 helper 约束）；会话创建失败必须留痕日志（先例 registry.go:104）。
7. 完全禁止：连接目标来自用户键盘输入（目标只能来自菜单选中的 DB 行）；明文口令/用户口令进任何日志；`_ =` 丢错误。
8. `main.go` 启动点参照 `monitor.StartFileSDWriter`（main.go:88）模式：env 关闭时内部静默不启动；进程生命周期即服务生命周期，不做优雅关闭。
9. 前端零改动；但后端有两处现有硬编码清单需加 "jump"：`handler/session.go:43` 的类型过滤白名单、`main.go:278` `sweepStaleRecords` 的 `type IN`（进程重启收敛僵尸 jump 会话）。均为既有行为的清单扩展，非前端改动。
10. 测试新增依赖 `github.com/glebarez/sqlite`（纯 Go 无 CGO，test-only）：**go.mod 现无任何 sqlite 驱动**（仅 gorm.io/driver/mysql），全仓库测试也没有 gorm 建库先例（handler/alert_webhook_test.go:83 注释明言「go.mod 无 sqlite」），因此不存在可「原样照抄」的内存库建法，本计划引入项目第一个 GORM 测试库并沉淀为 `service/jumpd` 内的 test helper。
