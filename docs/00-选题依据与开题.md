## 3.1 系统边界与范围判据（防跑题锚点）

> 论文题目关键词是**「私有云管理平台」**，而非「虚拟机管理工具」。所有功能取舍以是否支撑以下三个贡献点为判据：

| 贡献点 | 含义 | 支撑功能 |
|---|---|---|
| ① 轻量私有云 | 单二进制、低资源、**多宿主机纳管** | 宿主机管理、资源统一抽象、单二进制部署 |
| ② 真实 KVM 落地 | 非模拟，生命周期自动化 | VM 建/启停/删、镜像模板、存储池、网络 |
| ③ 操作审计可追溯 | 谁/何时/对什么/结果 | 审计中间件 + 查询 + 分布统计、角色权限 |

**与单机管理工具（virt-manager/Cockpit）的差异**：它们重在「单机全功能手工操作」；本平台重在「多机纳管 + API 标准化 + 审计留痕」。XML 直接编辑属工具思维，本平台以「结构化表单 + 模板」为主，原始 XML 编辑作为高级能力补充——这本身就是可写的设计点，不是减分项。

> 关于贡献点 ① 中「多宿主机纳管」的实现程度，需在论文中如实界定：目前已落地的是**纳管登记与状态采集**
> （宿主机 CRUD、`libvirt_uri` 入库、连通性测试与实时状态），而**跨宿主机的虚拟化操作尚未落地**——
> 虚拟化连接固定走本机 `qemu:///system`，`hosts.libvirt_uri` 未被用于建立连接。因此「多机纳管」当前
> 是资源模型与管理界面层面的支撑，真实可管的宿主机只有一台；跨机连接（`qemu+ssh://`）与连接池列为
> 后续工作（docs/08 §2.3）。写作时应避免表述为「已实现多宿主机虚拟机管理」。

## 3.2 功能范围（激进版，对齐 virt-manager 全功能）

| 模块 | 档位 | 状态 | 说明 |
|---|---|---|---|
| 认证 + 角色权限 | P0 | ✅ 已有 | JWT（验签锁定 HS256）+ admin/viewer；**viewer 为完全只读**（含控制台写入通道） |
| 宿主机纳管 + 状态 | P0 | ✅ 已有 | 多机纳管、连通性、实时状态 |
| VM 生命周期 | P0 | ✅ 已有 | 建/启停/重启/删（真实 KVM，go-libvirt 直连） |
| 镜像模板 | P0 | ✅ 已有 | 上传/列表/删除/模板标记 |
| 审计日志 | P0 | ✅ 已有 | 写入 + 查询 + 分布 |
| 仪表盘 | P0 | ✅ 已有 | 总览 + 状态分布 + 存储池/网络计数 |
| **网页控制台（noVNC）** | P1 | ✅ 已实现 | websockify + JSONTokenApi token 解析；另有 SSH 终端与免 IP 串口（仅 admin） |
| **存储池管理** | P1 | ✅ 已实现 | 池列表/创建/删除/卷管理（StorageVolCreateXML 建盘） |
| **网络管理** | P1 | ✅ 已实现 | 网络 CRUD/启停/XML（NAT 模板 + 自定义 XML） |
| **快照管理** | P1 | ✅ 已实现 | 创建/删除/回滚/列表（含描述与创建时间） |
| **XML 编辑（高级）** | P1 | ✅ 已实现 | dumpxml + 校验后 define |
| VM 详情增强（磁盘/网卡/硬件） | P1 | ✅ 已实现 | XML 编辑 + 磁盘/网卡可视化热插拔 |
| 硬件热添加（CPU/内存） | P2 | ✅ 已实现 | 调核/调内存（live+config），运行中受启动上限约束 |
| 监控集成（Prometheus） | P2 | ✅ 已实现 | 内建 exporter + 5 告警规则 + Grafana 9 面板（详见 docs/07） |
| 异步任务系统 | 追加 | ✅ 已实现 | 创建/删除/克隆/优雅关机后台化，202 + 轮询 |
| 控制台会话跟踪 | 追加 | ✅ 已实现 | 三链路埋点、强制断开、过期收敛 |
| 增量克隆（linked clone） | 追加 | ✅ 已实现 | 子卷 XML 声明 `<backingStore>`，`qemu-img info` 可见 backing file；克隆机 UUID 与全部网卡 MAC 重新生成（详见 docs/05 §6.7） |
| 稳定性 / 安全 / 正确性加固 | 追加 | ✅ 已实现 | 并发写串行化 + 后台协程容错；SQL/XML 注入面收敛、JWT 算法锁定、SSH 目标白名单；增量克隆语义更正、克隆机 MAC 唯一性、删卷三重守卫（详见 docs/06 第 5、6、9 章） |
| 多宿主机真实连接 | 追加 | ⚠️ 未实现 | `hosts.libvirt_uri` 已入库但从未用于建立连接，`virt.New()` 固定 `qemu:///system`；纳管登记与连通性测试可用，跨宿主机管理列为后续工作（docs/08 §2.3） |

> P1 已全部落地（存储池 → 网络 → 网页控制台 → 快照 → XML 编辑），P2 的硬件热调整与 Prometheus 监控亦已实现，平台已对齐 virt-manager 主要能力，可支撑完整演示与论文实现章节。功能完备后另做了三轮加固（稳定性 / 安全 / 正确性），构成论文第五、六章的工程深度素材——其中第三轮发现并修正了「文档声称已实现、实际并未实现」的增量克隆，是可写进绪论「研究工作的真实性」的一手材料。
