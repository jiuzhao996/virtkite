## 1. 部署形态

- 单后端二进制 + 前端静态产物。
- 运行 vmops 的机器本身不必是 KVM 宿主机，但被纳管宿主机需能执行 virsh。

## 2. 环境要求

- Go 1.21+ / Node.js 18+ / MySQL 8 / libvirt+qemu-kvm。
- 网页控制台：novnc / websockify（`sudo apt install novnc websockify`）。

## 3. 方式一：docker-compose 一键部署（推荐演示）

- 前端构建 → docker compose up -d --build。
- 容器：vmops-mysql / vmops-app / vmops-prometheus（:9090）/ vmops-grafana（:3000，admin/admin）。
- Dockerfile 适配前端说明。

## 4. 方式二：源码编译部署

- 数据库准备（Docker 或 init-db.sql）。
- 后端构建（go build）+ 启动。
- 前端构建（npm run build）→ web/dist。

## 5. 配置说明（.env）

| 变量 | 默认值 | 说明 |

## 6. 运维与排错

- 常见问题表（数据库连接失败、libvirt 连接失败、权限拒绝、前端白屏、审计 username 为空）。
- 网页控制台：需安装 `novnc` / `websockify`（`sudo apt install novnc websockify`）。
- 一键启动：`./start.sh --service`（后端 + noVNC 无人值守）/ `./start.sh --stop` 停止。
- libvirt 权限：运行用户需加入 `libvirt` 组（`sudo usermod -aG libvirt $USER`）。

### 6.1 任务 worker 运维

- 任务管理器单例（`tasks.NewManager`）：固定 4 worker、队列缓冲 128；队列满时 `Submit` 另起 goroutine 入队，保证 handler 不阻塞。
- worker 随进程退出即弃，无优雅关闭；重启导致残留 `pending/running` 任务由启动收敛标 `failed`（“服务重启，未完成任务已终止，请重新提交”），executor 非幂等、不自动重跑，需人工重新提交。
- 任务记录仅终态（success/failed）可删，可经任务中心页批量清理，避免 `tasks` 表无限增长。

### 6.2 会话清扫与启动收敛

- VNC 会话：websockify 解析 token 即刷新 `last_seen`；清扫器每 5 分钟将超 60 分钟无解析的 active VNC 会话标 `closed`（`Registry.StartSweeper`，`vncStaleAfter=60min`）。
- SSH/串口会话：WS 关闭即回写 `ended_at`；进程重启导致 WS 丢失时，`main.go sweepStaleRecords` 将残留 active 的 ssh/serial 会话标 `closed`。
- VNC token TTL：内存 `TokenStore` 默认 5 分钟过期，一次性语义（同 VM 新 token 使旧 token 失效）。

### 6.3 VNC 链路检查清单

1. `pgrep -af websockify` 确认中转进程存活（不保活，掉线则控制台全不可用）。
2. token 解析地址 `GET /api/vnc/token/:token` 内网可达（websockify `--token-source` 指向）。
3. 端口冲突：旧 `vmops.pid` 可能陈旧，按 AGENTS.md 流程核对 `:8080` 实际 PID 后重启。

### 6.4 Prometheus + Grafana 监控栈

- 后端内建 exporter：`GET /metrics` 公开（Prometheus 每 15s 抓取；生产环境用防火墙限制来源，仅监控内网可达）。
- compose 一键起栈：prometheus（`deploy/prometheus.yml` + `deploy/alerts.yml` 5 条规则）+ grafana（预置数据源与 `deploy/grafana-dashboard.json` 9 面板看板）。
- app 容器直通宿主机 libvirtd socket（`/var/run/libvirt/libvirt-sock` 挂载），否则容器内采集为空；宿主机直跑后端时改 prometheus.yml targets 为宿主机 IP:8080。
- 告警规则：VM 运行数归零 / Host CPU>85% / 池可用<10% / 任务堆积>10 / 单 VM CPU>90%（阈值按规模调）。
- 看板：运行中 VM 数 / 宿主机 CPU / 任务堆积（stat）+ VM CPU/内存/磁盘 IO/网络 IO / 宿主机 / 存储池使用率（timeseries）。

### 6.5 告警通知（Alertmanager）

- compose 新增 `alertmanager`（:9093），prometheus 经 `--alertmanager.url` 对接；规则见 `deploy/alerts.yml`。
- 默认 webhook 为占位地址（告警仅在 Alertmanager UI 可见 firing 状态）；生产替换为钉钉/飞书/企业微信机器人 webhook（`deploy/alertmanager.yml` 注释有示例）。
- 注意：`/metrics` 已从审计排除，否则 15s 一次抓取会淹没审计表。

## 8. E2E 回归

- `scripts/smoke.sh`：一键覆盖只读接口 + metrics + 创建/删除 task 全链路 + 硬件管理（23 项断言，`RESULT: PASS=x FAIL=0`），发布前必跑。
- 用法：`BASE=http://127.0.0.1:8080 ./scripts/smoke.sh`（写操作均用 `smoke-` 前缀并自动清理）.
