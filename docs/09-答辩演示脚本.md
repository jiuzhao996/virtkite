### 2.2 系统展示（8-10 分钟）

- [ ] 登录（admin）→ 仪表盘总览（宿主机/VM/存储池/网络计数）

- [ ] 存储池管理：池列表（容量/路径）→ 新建卷
- [ ] 网络管理：网络列表 → XML 查看
- [ ] 虚拟机生命周期：**创建（真实 KVM 建机，选择存储池）→ 启动 → 停止 → 重启 → 删除**
- [ ] **增量克隆与删除保护（正确性专题，建议单独留 2 分钟）**：克隆一台 VM → 终端 `qemu-img info <子盘>` 展示 `backing file:` 指向源盘、`qemu-img check` 报无错误 → 比对源机与克隆机 MAC（不同）→ 删除源虚拟机 → 任务详情里出现 `kept_volumes`「是增量克隆父盘，仍被 N 个子卷依赖」→ 再 `qemu-img check` 克隆机磁盘，仍无错误（证明 chain 未断）
- [ ] 快照管理：创建快照 → 列表 → 回滚 → 删除
- [ ] XML 编辑：查看 XML → 修改 vcpu → 保存（virsh dumpxml 对照）
- [ ] 网页控制台：启动 VM → 打开 noVNC 控制台（演示真实画面）
- [ ] **权限对照（换 user 账号登录）**：控制台页只剩图形控制台入口 + 只读说明条 → 连上后顶栏显示「只读观看（键鼠已禁用）」，键盘敲击无反应 → 变更按钮不可用 → 直接请求 `/terminal` 返回 403
- [ ] 审计中心：操作日志 + 控制台会话双 tab；会话筛选/强制断开
- [ ] **监控中心（建议单独留 2 分钟）**：告警列表（Alertmanager 实时数据）+ Grafana 大盘嵌在产品页内（Prometheus 15s 指标）→ 顺带演示仪表盘的历史曲线：刷新页面曲线**不清零**（Prometheus 当历史库，进页即回放）
- [ ] 个人中心：头像下拉 → 资料/改密/轮询偏好（强调全角色可用）
- [ ] 用户管理（admin）：建一个 viewer 账号 → 换登录演示权限对照（与前面 user 账号环节二选一即可）
- [ ] 演示后 `virsh list --all` / `vol-list` 对照（证明真实落地）

- [ ] 操作审计可追溯
- [ ] 监控一体化：告警/看板/历史曲线融合进产品（非三个独立控制台），Prometheus 当历史库

## 4. 常见提问与回答（FAQ）

- [ ] 为什么用 Go？→ 单二进制/低内存/并发
- [ ] 底层如何对接 libvirt？→ 纯 Go 的 go-libvirt 直连 RPC（unix socket），建盘走存储池/卷 API，域管理走 DomainDefineXML/Create 等
- [ ] 审计如何实现？→ 中间件与业务解耦
- [ ] 创建 VM 失败怎么办？→ 回滚 DB 记录
- [ ] 多宿主机如何纳管？→ 按「宿主机登记与状态采集」定位设计（SSH 连通性 ping + 资源状态），虚拟化连接统一走全局 LIBVIRT_URI，见下方「平台真的能管多台宿主机吗」一条
- [ ] 与 OpenStack/Proxmox 区别？→ 轻量/受限硬件可运行
- [ ] 前端为何用 Vue3？→ 组件化 + Element Plus
- [ ] 只读角色为什么能看图形控制台却不能用 SSH 终端？→ VNC 是观看画面（键鼠可在客户端禁用），SSH 终端与串口是对客户机的双向写入通道（串口在多数云镜像上直接是 root TTY），二者虽同为 GET 但读写语义不同
- [ ] 怎么保证只读真的只读？→ 后端按路径识别写入通道并 403，图形控制台由后端下发 `view_only` 标记、前端以 noVNC 只读模式加载；实测用例见 docs/06 第 5.2、5.3 节
- [ ] 平台如何防注入？→ 路径参数主键统一解析为数值后才进 ORM（避免内联条件退化为原始 SQL）；libvirt XML 全部由 `encoding/xml` 结构体序列化（元字符自动转义），接口层另做取值域白名单，两层纵深防御
- [ ] 有单元测试吗？→ 有，13 个用例分两个包：`service/console` 的 WebSocket 写入串行化 5 例、`service/virt` 的克隆语义 8 例，须带 `-race`；另做过反证实验（修复前写法在 `-race` 下报 6 条 DATA RACE），证明修复解决的是真实缺陷
- [ ] 后台任务出错会不会拖垮服务？→ 不会。Web 框架的 panic 恢复不覆盖自起协程，故 worker、清扫器、WebSocket 转发协程各自 `recover`；任务只置失败并写中文原因，堆栈只进日志
- [ ] 增量克隆是怎么实现的？怎么证明它真是增量的？→ 建子卷时在卷 XML 里声明 `<backingStore>` 指向父盘（等价 `qemu-img create -f qcow2 -F qcow2 -b`），子盘只存写入差异。证明不靠代码，靠三条外部命令：`qemu-img info` 有 `backing file:` 行、`virsh vol-dumpxml` 有 `<backingStore>` 节点、`qemu-img check` 报无错误。**这里有一段真实的返工**：早期实现用的是 `virsh vol-clone` 语义的 API，实测发现它做的是全量拷贝、子卷没有 backing file，「增量克隆」名不副实，第三轮加固时才更正过来（docs/06 §9.2 F-19）
- [ ] 克隆出来的两台机器为什么要换 MAC？→ libvirt 会拒绝 UUID 重复的域，但**不校验 MAC**，XML 里写了就照用。若沿用源机 MAC，两台不同时开机时一切正常、同时开机就同网段 ARP 冲突、网络双双不可用，且没有任何报错。所以克隆时必须逐块网卡重新生成 MAC（用 KVM 保留前缀 `52:54:00`），这条正确性由单元测试 U-Clone-04 守住
- [ ] 删除虚拟机会不会把别的机器的磁盘删了？→ 不会。删卷前有三重守卫：池外文件、镜像库登记的共享基镜像（「基于云镜像创建」是直接引用不拷贝）、仍被子卷当作 backing file 的增量克隆父盘，任一命中就保留，并把「哪些卷没删、为什么没删」写进任务结果的 `kept_volumes` 字段。设计上是「保留优先」：代价是先删父机再删子机时会留下孤儿文件，但一个垃圾文件可事后清理，一块损坏的在用磁盘不可恢复
- [ ] 平台真的能管多台宿主机吗？→ **目前不能，如实说明**。`hosts` 表定位为宿主机登记与状态采集（早期冒充多宿主纳管的 `libvirt_uri` 字段已在代码审查后砍除），`virt.New()` 固定连 `LIBVIRT_URI` 指向的 libvirt 端点，只有该端点可真实管理；跨宿主机连接（`qemu+ssh://`）与连接池列入后续工作（docs/08 §2.3）。跨宿主机连接（`qemu+ssh://`）与连接池列入后续工作（docs/08 §2.3）
