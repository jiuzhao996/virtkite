## 1. 演示环境准备

- [ ] 检查项：MySQL 容器运行、后端启动（本地用 `./start.sh`，已自动 `export SERVER_MODE=debug`；手动重启必须带 `SERVER_MODE=debug`，否则 release 校验拒绝启动）、前端 8080 可访问
- [ ] 预置数据：宿主机登记、2-3 台 VM、1 个镜像模板
- [ ] 预置账号：admin/password（管理员）、stu/123456（操作员 operator）、user/123456（普通用户 viewer）——登录页有演示账号提示条，构建时 `VITE_SHOW_DEMO_TIP=false` 可整体隐藏
- [ ] 预置授权：确认 stu 名下无授权（或记住已授权的 VM），供资产授权演示环节使用
- [ ] 断网不影响核心（本地全跑通）

## 2. 演示流程脚本

### 2.1 开场（1-2 分钟）

- [ ] 自我介绍 + 毕设题目 + 一句话定位

### 2.2 系统展示（8-10 分钟）

- [ ] 登录（admin）→ 仪表盘总览（宿主机/VM/存储池/网络计数）
- [ ] 宿主机管理：列表 + 连通性测试 + 实时状态
- [ ] 存储池管理：池列表（容量/路径）→ 新建卷
- [ ] 网络管理：网络列表 → XML 查看
- [ ] 虚拟机生命周期：**创建向导（四步：安装方式 → 计算资源 → 磁盘与网络 → 确认创建；云镜像方式现场演示前置条件检查、存储池可用空间预警与 cloud-init 折叠配置；ISO 方式演示按文件名自动识别操作系统）→ 启动 → 停止 → 重启 → 删除**
- [ ] **增量克隆与删除保护（正确性专题，建议单独留 2 分钟）**：克隆一台 VM → 终端 `qemu-img info <子盘>` 展示 `backing file:` 指向源盘、`qemu-img check` 报无错误 → 比对源机与克隆机 MAC（不同）→ 删除源虚拟机 → 任务详情里出现 `kept_volumes`「是增量克隆父盘，仍被 N 个子卷依赖」→ 再 `qemu-img check` 克隆机磁盘，仍无错误（证明 chain 未断）
- [ ] 快照管理：创建快照 → 列表 → 回滚 → 删除
- [ ] XML 编辑：查看 XML → 修改 vcpu → 保存（virsh dumpxml 对照）
- [ ] 网页控制台：启动 VM → 打开 noVNC 控制台（演示真实画面）
- [ ] **权限对照（换 user 账号登录）**：控制台页只剩图形控制台入口 + 只读说明条 → 连上后顶栏显示「只读观看（键鼠已禁用）」，键盘敲击无反应 → 变更按钮不可用 → 直接请求 `/terminal` 返回 403
- [ ] **资产授权演示（借鉴堡垒机 4A，建议单独留 2 分钟；三级角色故事：实验室管理员=admin / 学生=operator / 教师=viewer）**：admin 登录 → 打开某台 VM 详情 → 左栏「授权管理」→ 选 stu 授权（可设到期时间，如 2 小时）→ 退出换 stu 登录 → VM 列表**只见授权的那一台**，直接访问他机 URL 提示查无此项（404，未授权与不存在同响应，不泄露存在性）→ 换 user（viewer）登录访问监控中心四端点 403（操作员 stu 不受限）→ 回到 admin 收回授权 → stu 再看，VM 从列表消失（到期授权则到期后自动消失）
- [ ] 审计中心：操作日志 + 控制台会话双 tab；会话筛选/强制断开
- [ ] **监控中心（建议单独留 2 分钟）**：实时告警（Alertmanager 数据）+ 告警历史（webhook 入库追溯）+ Grafana 双看板嵌在产品页内（宿主机/虚拟机切换，Prometheus 15s 指标）+ file_sd 抓取目标预览卡 → 顺带演示仪表盘的历史曲线：刷新页面曲线**不清零**（Prometheus 当历史库，进页即回放）
- [ ] 个人中心：头像下拉 → 资料/改密/轮询偏好（强调全角色可用）
- [ ] 用户管理（admin）：建一个 viewer 账号 → 换登录演示权限对照（与前面 user 账号环节二选一即可）
- [ ] 演示后 `virsh list --all` / `vol-list` 对照（证明真实落地）

### 2.3 创新点强调（2-3 分钟）

- [ ] 操作审计可追溯
- [ ] **资产授权（堡垒机 4A 轻量版）**：VM 作为资产分配给学生/教师，**授权决定可见性**（未授权一律 404 查无此项），`expires_at` 到期自动软回收（查询时校验，无需清扫协程）；与三级角色（admin/operator/viewer）叠加构成「谁能看、谁能操作」双层收敛
- [ ] 监控一体化：告警/看板/历史曲线融合进产品（非三个独立控制台），Prometheus 当历史库
- [ ] 真实 KVM 建机（非模拟）
- [ ] 轻量单二进制部署
- [ ] 只读角色按「语义」而非「HTTP 方法」判定读写：SSH 终端与串口控制台协议层是 GET，实质是对客户机的写入通道，故对只读角色关闭；图形控制台改为客户端禁用键鼠的只读观看
- [ ] **功能语义以外部工具反证，而非以代码注释自证**：曾发现「增量克隆」在文档里被当作核心特性宣称、代码也调了名字看起来正确的 libvirt API，但 `qemu-img info` 证明产出的子卷根本没有 backing file（实际是全量拷贝）。修复后把三条外部命令固定为该功能的验收标准（详见 docs/06 §9.2 F-19）

## 4. 常见提问与回答（FAQ）

- [ ] 为什么用 Go？→ 单二进制/低内存/并发
- [ ] 底层如何对接 libvirt？→ 纯 Go 的 go-libvirt 直连 RPC（unix socket），建盘走存储池/卷 API，域管理走 DomainDefineXML/Create 等
- [ ] 审计如何实现？→ 中间件与业务解耦
- [ ] 创建 VM 失败怎么办？→ 回滚 DB 记录
- [ ] 多宿主机如何纳管？→ 按「宿主机登记与状态采集」定位设计（SSH 连通性 ping + 资源状态），虚拟化连接固定为本机 qemu:///system（unix socket 直连），见下方「平台真的能管多台宿主机吗」一条
- [ ] 与 OpenStack/Proxmox 区别？→ 轻量/受限硬件可运行
- [ ] 前端为何用 Vue3？→ 组件化 + Element Plus
- [ ] 只读角色为什么能看图形控制台却不能用 SSH 终端？→ VNC 是观看画面（键鼠可在客户端禁用），SSH 终端与串口是对客户机的双向写入通道（串口在多数云镜像上直接是 root TTY），二者虽同为 GET 但读写语义不同
- [ ] 怎么保证只读真的只读？→ 后端按路径识别写入通道并 403，图形控制台由后端下发 `view_only` 标记、前端以 noVNC 只读模式加载；实测用例见 docs/06 第 5.2、5.3 节
- [ ] 平台如何防注入？→ 路径参数主键统一解析为数值后才进 ORM（避免内联条件退化为原始 SQL）；libvirt XML 全部由 `encoding/xml` 结构体序列化（元字符自动转义），接口层另做取值域白名单，两层纵深防御
- [ ] 有单元测试吗？→ 有，142 个顶层测试函数 / 约 950 个子用例 / 7 个包（`go test -race` 全绿；console.Conn 并发写、克隆语义、参数校验、operator 角色矩阵、授权有效期、告警网关等），须带 `-race`；另做过反证实验（修复前写法在 `-race` 下报 6 条 DATA RACE），证明修复解决的是真实缺陷
- [ ] 后台任务出错会不会拖垮服务？→ 不会。Web 框架的 panic 恢复不覆盖自起协程，故 worker、清扫器、WebSocket 转发协程各自 `recover`；任务只置失败并写中文原因，堆栈只进日志
- [ ] 增量克隆是怎么实现的？怎么证明它真是增量的？→ 建子卷时在卷 XML 里声明 `<backingStore>` 指向父盘（等价 `qemu-img create -f qcow2 -F qcow2 -b`），子盘只存写入差异。证明不靠代码，靠三条外部命令：`qemu-img info` 有 `backing file:` 行、`virsh vol-dumpxml` 有 `<backingStore>` 节点、`qemu-img check` 报无错误。**这里有一段真实的返工**：早期实现用的是 `virsh vol-clone` 语义的 API，实测发现它做的是全量拷贝、子卷没有 backing file，「增量克隆」名不副实，第三轮加固时才更正过来（docs/06 §9.2 F-19）
- [ ] 克隆出来的两台机器为什么要换 MAC？→ libvirt 会拒绝 UUID 重复的域，但**不校验 MAC**，XML 里写了就照用。若沿用源机 MAC，两台不同时开机时一切正常、同时开机就同网段 ARP 冲突、网络双双不可用，且没有任何报错。所以克隆时必须逐块网卡重新生成 MAC（用 KVM 保留前缀 `52:54:00`），这条正确性由单元测试 U-Clone-04 守住
- [ ] 删除虚拟机会不会把别的机器的磁盘删了？→ 不会。删卷前有三重守卫：池外文件、镜像库登记的共享基镜像（「基于云镜像创建」是直接引用不拷贝）、仍被子卷当作 backing file 的增量克隆父盘，任一命中就保留，并把「哪些卷没删、为什么没删」写进任务结果的 `kept_volumes` 字段。设计上是「保留优先」：代价是先删父机再删子机时会留下孤儿文件，但一个垃圾文件可事后清理，一块损坏的在用磁盘不可恢复
- [ ] 平台真的能管多台宿主机吗？→ **目前不能，如实说明**。`hosts` 表定位为宿主机登记与状态采集（早期冒充多宿主纳管的 `libvirt_uri` 字段已在代码审查后砍除），`virt.New()` 固定连本机 `qemu:///system`，只有该端点可真实管理；跨宿主机连接（`qemu+ssh://`）与连接池列入后续工作（docs/08 §2.3）
- [ ] 未授权的用户能看到别人的虚拟机吗？→ 不能。这是资产授权的核心语义——**授权决定可见性**（借鉴堡垒机 4A）：非 admin 只见自己持有有效授权的 VM，未授权与不存在同响应（404 查无此项，不泄露存在性）；授权带 `expires_at` 到期自动失效，查询时校验、无需清扫协程；建机/克隆自动授权发起人，删 VM 回收授权
- [ ] 服务重启后任务会怎样？→ 启动时把遗留的 pending/running 任务统一置 failed（「服务重启，任务已中断」），不会留僵尸任务；executor 非幂等，不自动重跑，需重新提交
- [ ] 任务中心和审计中心的操作日志是不是重复了？→ 不是，二者是同一操作的**两个视角**，以删 VM 为例：审计记「发起」（请求瞬间入库：谁、何时、从哪个 IP、动作、响应码，一条请求一条记录，不可变）；任务记「执行」（后台数秒到数分钟的过程：进度、成败、`kept_volumes` 保留原因等结构化明细）。覆盖面也不同：任务只有 6 类耗时异步操作，**同步操作（暂停/改配置/改设置）只有审计有记录**——砍掉任何一个，另一边都无法补位。类比快递：审计是「下单记录」，任务是「物流跟踪」。二者经 vm_id 关联但不互相替代，与 JumpServer「工单/任务与操作日志分离」同构
- [ ] 审计中心里为什么有失败记录？能删吗？→ 审计中间件对**所有响应码 ≥400 的请求**记 failed——失败尝试恰恰是审计最有价值的部分（爆破、越权探测、扫接口都长这样）。常见来源：设置页保存触发取值校验（400）、未登录/登录态失效的请求（401，username 为空）。审计是**只增不改不删**的设计（与任务中心可「清理已完成」刻意相反）——合规留痕如果可删就失去了可信度
