## 1. 演示环境准备

- [ ] 检查项：MySQL 容器运行、后端启动（本地用 `./start.sh`，已自动 `export SERVER_MODE=debug`；手动重启必须带 `SERVER_MODE=debug`，否则 release 校验拒绝启动）、前端 8080 可访问
- [ ] 检查项：Docker 运行中（`docker ps` 能出结果）——容器管理与应用商店环节依赖；Docker 未运行时相关页面显示「不可用」提示，见 §5 故障预案
- [ ] 检查项：监控栈状态（`docker ps | grep -E "prometheus|grafana|alertmanager"`）——Grafana/Alertmanager 未启动时监控页有「未连接」兜底提示，属预期，见 §5 话术
- [ ] 预置数据：宿主机登记、2-3 台 VM（至少 1 台运行中）、1 个镜像模板、镜像库登记 1 个云镜像（供创建向导云镜像方式）
- [ ] 预置数据：`conf/appstore` 应用包目录在位（20 个应用）、宿主机可拉取镜像（提前 `docker pull nginx` 预热，避免现场拉镜像超时）
- [ ] 预置数据（告警推送演示可选）：系统设置 →「告警通知」配置飞书/钉钉机器人地址（现场配也只需 30 秒；未配置时告警只入库不出站，页面演示不受影响）
- [ ] 预置账号（演示账号表）：

| 账号 | 密码 | 角色 | 用途与权限差异（一句话） |
|------|------|------|------|
| `admin` | `Password1` | 管理员 | 主演示账号：全部权限，含用户/设置/计划任务/回收站/工具箱与授权管理 |
| `stu` | `123456` | 操作员（operator） | RBAC 演示账号：VM 全生命周期 + 三类控制台 + 商店装应用，但基础设施只读、用户/审计/设置不可达，且**只见被授权的 VM** |
| `user` | `123456` | 只读运维（viewer） | 对照组：纯只读 + VNC 只读观看，SSH/串口/监控中心一律 403 |

- [ ] 登录页有演示账号提示条，构建时 `VITE_SHOW_DEMO_TIP=false` 可整体隐藏
- [ ] 预置授权：确认 stu 名下无授权（或记住已授权的 VM），供资产授权演示环节使用
- [ ] 断网不影响核心（本地全跑通；AI 助手与镜像市场下载依赖外网，断网时跳过或提前备好）

## 2. 演示流程脚本

### 2.1 开场（1 分钟）

- [ ] 自我介绍 + 毕设题目 + 一句话定位（基于 KVM 的轻量级私有云管理平台；v3 起参考 1Panel 设计模式吸收运维面板能力，但保持 KVM 私有云定位）
- [ ] 话术要点：「一条主线是虚拟机全生命周期，一条辅线是把运维面板的常用能力（容器/应用商店/计划任务/AI 助手）收进同一个浏览器入口」

### 2.2 系统展示（12-15 分钟，按序号即演示动线；时间紧优先砍 ②拓扑图 与 ⑨计划任务，单环节按下限执行）

**① 登录 + 仪表盘三 tab（约 1.5 分钟）**

- [ ] 操作：admin 登录 → 仪表盘「概览」tab：统计卡（可点击跳转）、状态分布、资源容量/超分卡 → 切「监控」tab：实时告警 + Grafana 看板 + 告警历史 → 切「拓扑」tab：资产从属关系图
- [ ] 话术：「概览回答『平台现在什么状态』，监控回答『出没出事』——告警、看板、历史曲线融在产品里，不是三个独立控制台」；历史曲线刷新不清零（Prometheus 当历史库）
- [ ] 兜底：Grafana 未启动时看板区显示「未连接」提示层——如实说「监控栈容器未启动时的预期兜底，compose up 即出」（见 §5）

**② 拓扑（约 30 秒，时间紧可跳；已并入仪表盘第三 tab）**

- [ ] 操作：仪表盘「拓扑」tab → 宿主机-存储池-虚拟机从属关系，按状态过滤
- [ ] 话术：「一张图看清资产从属：池按容量、虚拟机按状态着色」

**③ 创建向导（约 2 分钟）**

- [ ] 操作：虚拟机 → 新建 → 四步向导（安装方式 → 计算资源 → 磁盘与网络 → 确认创建）；选「云镜像」方式：演示前置条件检查、存储池可用空间与超额预警、cloud-init 折叠配置（主机名/用户/密码/SSH 公钥）、增量盘标注文案
- [ ] 话术：「云镜像方式基于 qcow2 backing 创建增量盘——不复制镜像文件，初始只占元数据级空间，这是 KVM linked clone 的能力」；「cloud-init 负责开机自动注入用户与网络，装完即用」
- [ ] 提交后任务中心出 202 任务轮询到成功（异步任务系统的现场证据）

**④ 增量克隆与删除保护（正确性专题，约 2 分钟，务必保留）**

- [ ] 克隆一台 VM → 终端 `qemu-img info <子盘>` 展示 `backing file:` 指向源盘、`qemu-img check` 报无错误 → 比对源机与克隆机 MAC（每块网卡都不同）→ 删除源虚拟机 → 任务详情里出现 `kept_volumes`「是增量克隆父盘，仍被 N 个子卷依赖」→ 再 `qemu-img check` 克隆机磁盘，仍无错误（证明 chain 未断）
- [ ] 话术：「功能语义用外部工具反证，不用代码注释自证——这是本项目最重要的一次返工换来的验收标准」

**⑤ VM 详情页（约 1.5 分钟）**

- [ ] 操作：进入一台 VM 详情 → 概览信息行 → 硬件面板（磁盘/网卡卡：一键建盘挂载、补齐标准设备）→ 快照 tab（创建→列表→回滚）→ 左栏「授权管理」（admin）：给 stu 授权一台 VM（设 2 小时到期）→ 父卷链展示（增量系统盘显示 backing 父盘）
- [ ] 话术：「硬件热插拔对标 virt-manager；授权管理是堡垒机 4A 的轻量版——授权决定可见性，等会儿换 stu 账号验收」

**⑥ 控制台三入口（约 1.5 分钟，重点 SSH）**

- [ ] 操作：详情页「控制台」→ 控制台页三入口：VNC 图形（真实桌面画面）/ SSH 终端（输 IP 口令连上，敲几条命令）/ 串口控制台（免 IP 直连串口 TTY）
- [ ] 话术：「SSH 终端是完整 shell，串口不依赖网络配置——云镜像没配 IP 也能进」；「会话进审计中心，管理员可强制断开」
- [ ] 兜底：串口无输出 → serial-getty 排障话术（见 §5）

**⑦ 容器管理（约 1.5 分钟）**

- [ ] 操作：侧栏「Docker 管理」→ 容器 tab（状态 chips 计数、资源占用列、日志抽屉：跟随/下载/tail）→ **「创建容器」（v3.4）：填名称、镜像下拉选一个本地镜像（如 busybox）、加一条端口映射、重启策略选 always → 创建，列表即时出现** → 镜像/网络/卷/编排 tab 快速过 → 选中一个容器开「容器终端」敲命令 → 审计中心可见容器终端会话、可强断
- [ ] 话术（创建容器）：「表单字段直接映射 docker run 参数——端口/挂载/环境变量/重启策略，前后端双层校验；本地没有的镜像会自动拉取」
- [ ] 话术：「宿主机上不止虚拟机——KVM 域加 Docker 容器统一面板，这是 v3 参考 1Panel 补齐的第二运行时；容器终端与 SSH 终端同一套写锁与会话治理」

**⑧ 应用商店（约 1.5 分钟）**

- [ ] 操作：侧栏「应用商店」→ 20 个应用卡片 → 选 nginx → 动态表单（端口/名称等，说明「表单由应用包 data.yml 声明式定义」）→ 安装 → 任务轮询 → 容器管理出现该容器 → 浏览器访问装好的页面
- [ ] 话术：「应用包是声明式的：元数据 + 表单定义 + compose 模板三件套，安装就是写 .env 后 docker compose up——加一个新应用不需要改平台代码」（参考 1Panel GPLv3 设计模式）
- [ ] 兜底：Docker 未运行时页面顶部有 alert 且禁用安装（见 §5）；拉镜像慢属网络问题，话术「可配镜像加速」

**⑨ 计划任务（约 1 分钟）**

- [ ] 操作：侧栏「计划任务」→ 新建：五字段 cron 表达式（输入时下方预览接下来 5 次执行时刻）+ 动作（定时快照 / 数据库备份）→ 保存 → 立即运行一次 → 执行记录可见成败与耗时
- [ ] 话术：「定时快照和数据库备份不再靠人记，执行历史可追溯」

**⑩ AI 运维助手（约 1 分钟，高潮位）**

- [ ] 操作：顶栏 AI 助手按钮（聊天图标）打开抽屉 → 打开「携带平台上下文」→ 问「我平台上几台虚拟机在跑？哪台 CPU 最高？」→ 流式回答引用真实数据
- [ ] 话术：「OpenAI 兼容接口的纯代理——Key 只存服务端；带上下文时后端注入平台摘要，所以它『看得懂这台服务器』；它只读不写，没有任何操作平台的能力」

**⑪ 审计中心（约 45 秒）**

- [ ] 操作：审计中心双 tab：操作日志（筛选刚才的操作，失败记录也在）+ 控制台会话（刚才的 SSH/容器终端会话，演示强制断开）
- [ ] 话术：「审计只增不改不删；失败尝试恰恰是最有价值的审计记录」

**⑫ RBAC 与资产授权（切 stu 账号，约 2 分钟，务必保留）**

- [ ] 操作：退出 → stu 登录 → VM 列表**只见被授权的那一台**，直输他机 URL 提示查无此项（404）→ 侧栏无用户/审计/设置/计划任务/回收站 → 存储池只读（无新建钮）→ 换 user（viewer）登录：控制台只剩图形入口且「只读观看（键鼠已禁用）」，直接请求 `/terminal` 403、监控中心 403 → 回 admin 收回授权 → stu 再看 VM 消失
- [ ] 话术：「三级角色回答『谁能做什么』，资产授权回答『谁能看到哪台』——未授权与不存在同响应，不泄露存在性；到期授权查询时即时失效」

**⑬ SSH 跳板（约 1.5 分钟，高潮位备选；原生终端演示）**

- [ ] 操作：本机终端 `ssh stu@<宿主机IP> -p 2222`（密码 123456）→ 菜单**只列出 stu 被授权且运行中、已托管凭据的虚拟机**（对照 admin 登录可见全量）→ 按数字直达 VM shell → `exit` 回菜单 → `q` 断开
- [ ] 话术：「这是 JumpServer 式的入口——认证、授权、账号、审计在 Web 和原生终端两条通道都成立；连接目标由服务端从授权库决定，用户只能选单，注入面天然消失」
- [ ] 加分演示：连上后在 shell 里敲 `rm -rf /tmp/x` → 红字「危险命令已被安全策略拦截并审计」→ 审计中心当场出现该记录（命令不执行、文件安然无恙）；`scp`/`ssh -L` 端口转发均被服务端拒绝
- [ ] 加分演示：「资产申请」页——stu 选一台运行中 VM 填理由提交 → admin 审批队列批准（可调时长）→ stu 的虚拟机列表**当场多出这台机器**；到期自动收回
- [ ] 兜底：jms 参照容器占用 2222 时改用 `JUMPD_PORT`；「菜单里没有我的机器」= 未授权/未运行/无 IP/未托管凭据四条件缺一，回 Web 端补齐（见 §5）

**⑭ 回收站 + 收尾（约 1 分钟）**

- [ ] 操作：admin 删一台测试 VM → 侧栏「回收站」→ 软删记录可见 → 恢复（或演示彻底清除）
- [ ] 话术：「删错的后悔药；配合删卷三重守卫——『宁可留垃圾文件，不可损坏在用磁盘』是本项目对破坏性操作的统一立场」
- [ ] 演示后 `virsh list --all` / `docker ps` 对照（证明虚拟机与容器都真实落地）

### 2.3 创新点强调（2-3 分钟）

- [ ] 操作审计可追溯
- [ ] **资产授权（堡垒机 4A 轻量版）**：VM 作为资产分配给成员/同学，**授权决定可见性**（未授权一律 404 查无此项），`expires_at` 到期自动软回收（查询时校验，无需清扫协程）；与三级角色（admin/operator/viewer）叠加构成「谁能看、谁能操作」双层收敛
- [ ] 监控一体化：告警/看板/历史曲线/日志（Loki）融合进产品（非独立控制台），Prometheus 当历史库
- [ ] **告警出站通知**（v3.4）：告警不仅进页面，还推飞书/钉钉——「值班的人不用盯着屏幕，手机先知道」；去重语义（同指纹重复告警只推一次，恢复后再触发才再推）是运维通知的正规做法
- [ ] 真实 KVM 建机（非模拟）+ **KVM 域 + Docker 容器「双运行时」统一面板**（v3）：两个运行时共用同一套封装纪律、任务队列与会话治理
- [ ] **声明式应用商店**（v3，参考 1Panel GPLv3 设计模式）：应用包三件套声明一切，安装 = 写 .env + compose up，平台代码零改动扩应用
- [ ] **AI 运维助手带平台上下文**（v3）：OpenAI 兼容纯代理 + 环境摘要注入，「看得懂这台服务器」且严格只读
- [ ] **凭据加密托管**（v3）：AES-256-GCM（主密钥不落库 + 每条随机盐），明文不出服务端
- [ ] 轻量单二进制部署
- [ ] 只读角色按「语义」而非「HTTP 方法」判定读写：SSH 终端与串口控制台协议层是 GET，实质是对客户机的写入通道，故对只读角色关闭；图形控制台改为客户端禁用键鼠的只读观看
- [ ] **功能语义以外部工具反证，而非以代码注释自证**：曾发现「增量克隆」在文档里被当作核心特性宣称、代码也调了名字看起来正确的 libvirt API，但 `qemu-img info` 证明产出的子卷根本没有 backing file（实际是全量拷贝）。修复后把三条外部命令固定为该功能的验收标准（详见 docs/06 §9.2 F-19）

## 4. 常见提问与回答（FAQ）

- [ ] 为什么用 Go？→ 单二进制/低内存/并发
- [ ] 底层如何对接 libvirt？→ 纯 Go 的 go-libvirt 直连 RPC（unix socket），建盘走存储池/卷 API，域管理走 DomainDefineXML/Create 等
- [ ] 审计如何实现？→ 中间件与业务解耦
- [ ] 创建 VM 失败怎么办？→ 回滚 DB 记录
- [ ] 多宿主机如何纳管？→ 按「宿主机登记与状态采集」定位设计（SSH 连通性 ping + 资源状态），虚拟化连接固定为本机 qemu:///system（unix socket 直连），见下方「平台真的能管多台宿主机吗」一条
- [ ] 与 OpenStack/Proxmox 区别？→ 轻量/受限硬件可运行
- [ ] 前端为何用 Vue3？→ 组件化 + Element Plus
- [ ] 只读角色为什么能看图形控制台却不能用 SSH 终端？→ VNC 是观看画面（键鼠可在客户端禁用），SSH 终端与串口是对客户机的双向写入通道（串口在多数云镜像上直接是 root TTY），二者虽同为 GET 但读写语义不同
- [ ] 怎么保证只读真的只读？→ 后端按路径识别写入通道并 403，图形控制台由后端下发 `view_only` 标记、前端以 noVNC 只读模式加载；实测用例见 docs/06 第 5.2、5.3 节
- [ ] 平台如何防注入？→ 路径参数主键统一解析为数值后才进 ORM（避免内联条件退化为原始 SQL）；libvirt XML 全部由 `encoding/xml` 结构体序列化（元字符自动转义），接口层另做取值域白名单，两层纵深防御
- [ ] 有单元测试吗？→ 有，209 个顶层测试函数 / 约 1100 个子用例 / 14 个测试包（`go test -race` 全绿；console.Conn 并发写、克隆语义、参数校验、operator 角色矩阵、授权有效期、告警网关、凭据加解密、cron 解析、应用包解析等），须带 `-race`；另做过反证实验（修复前写法在 `-race` 下报 6 条 DATA RACE），证明修复解决的是真实缺陷
- [ ] 为什么做容器管理和应用商店？跟 1Panel 是什么关系？→ 真实宿主机上负载不止 KVM 域，容器与自托管中间件同样要管理入口——这是运维面板的主场，本项目参考 1Panel（GPLv3）的设计模式（容器面板信息架构、声明式应用包、计划任务交互），未引入其代码与组件库；差异在定位：1Panel 是建站向服务器面板，本项目保持 KVM 私有云定位，容器是「第二运行时」而非主线
- [ ] AI 助手会不会乱操作平台？→ 不会，它是 OpenAI 兼容接口的**纯只读代理**：只做问答转发，不具备任何写操作能力；带上下文时后端注入平台环境摘要（VM/容器/告警统计），Key 只存服务端不下发前端；viewer 不可用（403）
- [ ] 保存的虚拟机口令安全吗？→ AES-256-GCM 加密落库：主密钥运行时注入不落库、每条记录独立随机盐，数据库泄露拿不到明文；消费方（文件管理/应用安装）在后端解密，明文不出服务端不进日志；边界如实说明——不防「应用与数据库同时失守」，那属主机沦陷
- [ ] 应用商店装的应用出问题怎么办？→ 安装走异步任务（失败原因透出镜像名），卸载保留数据目录；安装前有端口占用预检；容器层面可在 Docker 管理里直接看日志/终端排查
- [ ] 后台任务出错会不会拖垮服务？→ 不会。Web 框架的 panic 恢复不覆盖自起协程，故 worker、清扫器、WebSocket 转发协程各自 `recover`；任务只置失败并写中文原因，堆栈只进日志
- [ ] 增量克隆是怎么实现的？怎么证明它真是增量的？→ 建子卷时在卷 XML 里声明 `<backingStore>` 指向父盘（等价 `qemu-img create -f qcow2 -F qcow2 -b`），子盘只存写入差异。证明不靠代码，靠三条外部命令：`qemu-img info` 有 `backing file:` 行、`virsh vol-dumpxml` 有 `<backingStore>` 节点、`qemu-img check` 报无错误。**这里有一段真实的返工**：早期实现用的是 `virsh vol-clone` 语义的 API，实测发现它做的是全量拷贝、子卷没有 backing file，「增量克隆」名不副实，第三轮加固时才更正过来（docs/06 §9.2 F-19）
- [ ] 克隆出来的两台机器为什么要换 MAC？→ libvirt 会拒绝 UUID 重复的域，但**不校验 MAC**，XML 里写了就照用。若沿用源机 MAC，两台不同时开机时一切正常、同时开机就同网段 ARP 冲突、网络双双不可用，且没有任何报错。所以克隆时必须逐块网卡重新生成 MAC（用 KVM 保留前缀 `52:54:00`），这条正确性由单元测试 U-Clone-04 守住
- [ ] 删除虚拟机会不会把别的机器的磁盘删了？→ 不会。删卷前有三重守卫：池外文件、镜像库登记的共享基镜像（「基于云镜像创建」是直接引用不拷贝）、仍被子卷当作 backing file 的增量克隆父盘，任一命中就保留，并把「哪些卷没删、为什么没删」写进任务结果的 `kept_volumes` 字段。设计上是「保留优先」：代价是先删父机再删子机时会留下孤儿文件，但一个垃圾文件可事后清理，一块损坏的在用磁盘不可恢复
- [ ] 平台真的能管多台宿主机吗？→ **目前不能，如实说明**。`hosts` 表定位为宿主机登记与状态采集（早期冒充多宿主纳管的 `libvirt_uri` 字段已在代码审查后砍除），`virt.New()` 固定连本机 `qemu:///system`，只有该端点可真实管理；跨宿主机连接（`qemu+ssh://`）与连接池列入后续工作（docs/08 §2.3）
- [ ] 未授权的用户能看到别人的虚拟机吗？→ 不能。这是资产授权的核心语义——**授权决定可见性**（借鉴堡垒机 4A）：非 admin 只见自己持有有效授权的 VM，未授权与不存在同响应（404 查无此项，不泄露存在性）；授权带 `expires_at` 到期自动失效，查询时校验、无需清扫协程；建机/克隆自动授权发起人，删 VM 回收授权
- [ ] 服务重启后任务会怎样？→ 启动时把遗留的 pending/running 任务统一置 failed（「服务重启，任务已中断」），不会留僵尸任务；executor 非幂等，不自动重跑，需重新提交
- [ ] 任务中心和审计中心的操作日志是不是重复了？→ 不是，二者是同一操作的**两个视角**，以删 VM 为例：审计记「发起」（请求瞬间入库：谁、何时、从哪个 IP、动作、响应码，一条请求一条记录，不可变）；任务记「执行」（后台数秒到数分钟的过程：进度、成败、`kept_volumes` 保留原因等结构化明细）。覆盖面也不同：任务只有 6 类耗时异步操作，**同步操作（暂停/改配置/改设置）只有审计有记录**——砍掉任何一个，另一边都无法补位。类比快递：审计是「下单记录」，任务是「物流跟踪」。二者经 vm_id 关联但不互相替代，与 JumpServer「工单/任务与操作日志分离」同构
- [ ] 审计中心里为什么有失败记录？能删吗？→ 审计中间件对**所有响应码 ≥400 的请求**记 failed——失败尝试恰恰是审计最有价值的部分（爆破、越权探测、扫接口都长这样）。常见来源：设置页保存触发取值校验（400）、未登录/登录态失效的请求（401，username 为空）。审计是**只增不改不删**的设计（与任务中心可「清理已完成」刻意相反）——合规留痕如果可删就失去了可信度

## 5. 故障预案（演示翻车兜底话术）

### 5.x SSH 跳板环节兜底（⑬）

| 症状 | 原因 | 话术/处置 |
|---|---|---|
| 连接被拒「Connection refused」 | `JUMPD_ENABLED` 未开 / 端口被占（JumpServer 参照容器曾占 2222） | 「跳板默认关闭，部署侧显式开启」；`ss -ltnp \| grep 2222` 核对监听，`grep jumpd vmops.log` 看启动日志 |
| 登录失败次数过多 | 同 IP 1 分钟 5 次失败锁定（限流按设计工作） | 如实说「这是防爆破限流，1 分钟窗口自动恢复」——正是演示点 |
| 菜单里没有目标机器 | 四条件缺一：未授权 / 非运行中 / 无 IP / 未托管凭据 | 「fail-closed：不可达的选项根本不出现」；回 Web 端补凭据/开机 |
| 选中后提示「凭据解密失败」 | 历史凭据主密钥不匹配（CREDENTIAL_MASTER_KEY 轮换未 rekey） | 跑 `scripts/credential-rekey --apply`（先 dry-run 看条数） |
| 选中后提示「连接虚拟机失败」 | 目标 SSH 不可达 / 主机指纹变化 | 指纹变化有专门文案（TOFU 防中间人，删记录重连）；其余查 VM 内 sshd |


| 故障场景 | 现象 | 兜底话术 / 处置 |
|---|---|---|
| Grafana 未启动 | 监控 tab 看板区显示「Grafana 未连接 + 重试」提示层 | **属预期行为**：「后端对 Grafana 做了探活，容器未启动时前端直接亮未连接提示，而不是渲染一个白屏 iframe——这本身是探活兜底设计的演示」；告警列表/告警历史/file-sd 不受影响，照常讲；时间允许可 `docker compose up -d grafana` 后点重试 |
| Alertmanager 不可达 | 实时告警列表空或页内提示不可达（后端代理 502） | 「告警链路是 Prometheus → Alertmanager → webhook 入库，AM 不在线时实时列表降级，但**告警历史是 webhook 推送时落库的**，历史查询不受影响」——顺势讲「代理 + 入库」双通道设计 |
| Docker 未运行 | Docker 管理页/应用商店顶部 alert「Docker 不可用」，安装按钮禁用 | **属预期行为**：「依赖 Docker 的功能在服务不可用时有页面级降级提示，而不是报错堆栈」；跳过 ⑦⑧ 环节，把容器部分改为讲架构（dockerx 封装 + 容器终端链路） |
| 串口控制台无输出 / 敲键无反应 | 串口页空白 | 排障话术：「串口要有输出需要客户机内核配了 `console=ttyS0` 且 `serial-getty@ttyS0` 起了 getty——云镜像一般都有，Rocky 最小安装这类没有；这是 guest 侧配置问题，不是平台链路问题」。现场处置：切 SSH 终端演示（链路独立），或在 SSH 里 `systemctl start serial-getty@ttyS0` 后回串口页演示；另说明「串口是单消费者，多标签页同连会互踢」 |
| 任务队列繁忙 / 任务一直 pending | 提交后报「任务队列繁忙，请稍后重试」或轮询迟迟不终态 | 「任务队列是有界队列 + 3 秒等待上限，满了如实把背压回传给前端，而不是无限堆积协程——这是刻意设计」；现场等 10 秒重试即可（4 个 worker 很快排空） |
| 商店安装拉镜像慢/超时 | 安装任务长时间 running，错误透出镜像名 | 「拉镜像走公网，可配镜像加速器；安装任务失败会透出具体镜像名，卸载重装即可」；答辩前预热 `docker pull` 可避免 |
| 前端白屏 / 静态资源 404 | 页面空白，console 报 MIME text/html | 是「后端进程锁着旧 index.html、前端新构建哈希对不上」的已知坑，**重启后端**（`go build -o vmops . && ./start.sh`）即恢复——不是前端代码问题 |
