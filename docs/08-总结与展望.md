## 1. 工作总结

已完成功能回顾：认证与 RBAC 只读角色、宿主机管理、VM 生命周期、异步任务系统、会话跟踪与控制台三链路、镜像与模板、增量克隆与 cloud-init、硬件热管理（磁盘/网卡/核/内存）、存储池、网络、快照、审计、仪表盘、任务中心/会话管理/系统设置前端，以及创建向导与列表实时化。

核心成果：真实 KVM 建机、耗时操作异步化（202 + 轮询）、控制台会话可观测可收敛、增量克隆节磁盘、操作审计可追溯、单二进制轻量部署。

功能完备之后另做了三轮加固，分别针对**进程稳定性**、**外部安全**与**功能正确性**。前两轮的共同思路是
「把隐性假设显式化」：并发写 WebSocket 假设了库允许多协程写、后台协程假设了框架会兜住 panic、路径参数
假设了 ORM 会参数化、XML 拼接假设了输入不含元字符、`alg` 假设了客户端不会改、密钥校验假设了默认值不
存在——这些假设逐条被证否并修正。其中「viewer 完全只读」这一结论值得单独强调：加固前只读角色可经 SSH
终端与串口控制台取得客户机内的任意写权限（两者协议层是 GET，实质是双向写入通道），角色名不副实；加固
后二者对 viewer 关闭，图形控制台改为客户端禁用键鼠的只读观看，只读语义才真正成立。

第三轮（正确性）的性质不同，也是三轮里最值得写进论文的一段：它修的不是「会崩」或「会被攻击」的问题，
而是**「文档声称已实现、实际并未实现」的问题**。最典型的一例是「增量克隆」——README 与多篇设计文档都
把它列为核心特性，代码里也确实调用了一个名字看起来完全正确的 libvirt API（`StorageVolCreateXMLFrom`，
即 `virsh vol-clone`），注释还写着「libvirt 自动写 qcow2 backing file」；但实测该 API 做的是全量数据
拷贝，产出的子卷根本没有 backing file。因为整盘拷贝出来的虚拟机同样能正常开机，这个缺陷在相当长的时间
里没有暴露。由此得到的方法论结论是：**「调用了哪个 API」不构成功能语义的证明，必须由该功能的外部可观测
结果反证**（此处即 `qemu-img info` 的输出）。修复后把「子盘有 `backing file:` 行 / `vol-dumpxml` 有
`<backingStore>` 节点 / `qemu-img check` 无错误」三条外部命令固定为该功能的验收方式。

同一轮里另有两个「不报错的错误」：克隆机沿用源机 MAC（libvirt 拒绝重复 UUID 但不校验 MAC，因此直到两台
同时开机、同网段 ARP 冲突才会发现），以及删除虚拟机会误删被其他机器依赖的共享卷（真正实现 backing chain
后，误删父盘意味着所有子机磁盘不可恢复）。两者的修复方式也反映了两条设计取向：把配置派生抽成不依赖
libvirt 的纯函数以便单元测试断言；破坏性操作按「保留优先」而非「删干净优先」设计，并把「哪些卷没删、
为什么没删」回传给用户。

工程实践：Go + Vue3 + MySQL + libvirt 全栈；virt 封装层统一 libvirt 出口；任务队列与会话注册表两个后台子系统；
单元测试从 0 补到 13 例（`go test -race`，两个包），并以反证实验确认修复有效。

| 模块 | 工作量要点 |

## 2. 后续工作

### 2.1 监控子系统（ exporter + 看板已落地）

- ✅ 已落地：后端内建 Prometheus exporter（`GET /metrics`，VM/宿主机/存储池/任务 4 类指标）+ 5 条告警规则 + Grafana 9 面板看板 + compose 一键监控栈。
- ✅ 已落地（UX/发布批次）：监控栈全容器化（grafana 13.2.1 / prometheus v3.14.0 / alertmanager v0.34.0）；
  产品内「监控中心」页融合告警代理与 Grafana kiosk 看板；历史性能曲线把 Prometheus 当历史库
  （query_range 回放，三处曲线刷新不再清零）；仪表盘告警概览卡。
- 待做：Alertmanager 告警网关（去重/分级/多通道）与 alertnotify 对接。
- 待做：服务发现闭环（平台建 VM → 自动被监控，目前靠 label 自动出现，缺 file_sd/target 元数据）。
- 待做：Alertmanager 告警网关（去重/分级/多通道）与 alertnotify 对接。
- 待做：服务发现闭环（平台建 VM → 自动被监控，目前靠 label 自动出现，缺 file_sd/target 元数据）。

### 2.2 混合云接入

- frp + WireGuard 打通家庭私有云与公有云。
- 域名规划（ops.jzops.fun / monitor.jzops.fun）。
- 双通道分工：frp 对外服务暴露、WireGuard 对内大流量。

### 2.3 功能扩展

- 存储池（Ceph RBD）。
- 腾讯云 CVM 纳管。
- **多宿主机真正落地**：`hosts` 表的 `libvirt_uri` 已入库、已在系统设置页展示，但**从未用于建立连接**——`virt.New()` 固定连 `qemu:///system`，因此当前只有运行后端的这台机器真实可管，多宿主机纳管仍是空壳。后续需按 host 维度维护连接（`qemu+ssh://` 或 `qemu+tls://`）并做连接池与并发复用。
- ~~孤儿卷清理~~：已实现 `cleanup_volumes` 后台任务（存储池页「清理孤儿卷」按钮），复用删卷守卫的引用判定反向使用——零引用才删，任一命中保留并记录原因。

### 2.4 工程优化

- service/repository 分层。
- 参数校验与错误处理（已完成路径参数主键、存储路径、卷格式、网关、`ssh_ip`、SSH 目标六类校验，中间件响应格式统一，以及 handler 层内部错误泄漏的最后一处收口；其余请求体字段的校验仍分散在各 handler，待抽公共校验层）。
- 测试覆盖（已扩至 129 个顶层测试函数 / 约 950 个子用例 / 6 个包，`go test -race ./...` 全绿：handler 层认证限流/历史曲线/删卷守卫/参数解析/响应格式/终端/校验，service 层 setting/tasks/virt/console。libvirt 直连函数仍需接口抽象或 fake 才可测，是下一步方向）。
- 静态检查补全：安装 `golangci-lint` 并接入（当前本机未安装，深度 lint 未执行；现有 `.golangci.yml` 为 v1 schema，装 v2.x 需先迁移字段名）。
- 一致性收口：`service/tasks/vm_tasks.go` 尚有 5 处 `"shut off"` 字面量未换成 `model.VMStatusShutOff`。
- 前端补齐：`POST /api/vms/import` 的 `errors` 数组后端已返回中文原因，但 `VmList.vue` 未消费，单台导入失败的原因目前不呈现给用户。
- 剩余安全项：网络与域的原始 XML 定义接口做结构校验、`/metrics` 加鉴权或独立监听端口、Web 终端引入主机密钥信任策略。（登录失败限流与 release CORS 禁 `*` 已在本轮落地。）
- 日志优化（当前为标准库 `log` 文本输出，可迁移结构化日志便于检索）。

> 说明：noVNC 网页控制台、快照/克隆、存储池、网络管理等早期展望项已在前几轮实现，不再列为后续工作。

### 2.5 本轮（UX/发布批次）已落地成果一览

- **产品化补全**：监控中心（告警代理 + Grafana 嵌入）、审计中心（操作日志 + 会话双 tab）、
  个人中心、用户管理页、任务详情抽屉（kept_volumes 删卷保护可视化）、系统设置做实（KV + resolver 即时生效）。
- **信息架构改造**：侧边栏五组折叠菜单、顶栏任务铃与头像下拉、详情页动态标题——对标主流云控制台的布局分工
  （侧边栏放页面、顶栏放全局与个人入口）。
- **体验修复**：历史性能曲线（Prometheus 当历史库，三处曲线刷新不再清零）。
- **安全加固**：登录失败限流、release 模式 CORS 禁 `*` 启动校验、用户角色白名单。
- **部署形态**：监控栈全容器化 + websockify 容器服务，一键 `docker compose up -d` 全栈闭环。
