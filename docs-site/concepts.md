# 五分钟理解核心概念

第一次接触虚拟化的同学，先把这几个词搞明白——平台里每个菜单都对应其中一个。

## 宿主机（Host）

就是**装了平台的那台物理服务器**（或大规格虚拟机）。所有虚拟机都跑在它身上。平台左侧菜单「宿主机」显示的就是它的 CPU / 内存 / 磁盘水位。

> 类比：宿主机是**公寓楼**，虚拟机是楼里的**房间**。

## 虚拟机（VM）

用软件模拟出来的一台"独立电脑"：有自己的操作系统、IP、磁盘。它和隔壁虚拟机完全隔离——学生 A 弄崩了自己的机器，不影响任何人。

> 类比：房间有独立门锁。创建一台 = 在公寓楼里隔出一间房。

## 镜像（Image）

**装好操作系统的"模板盘"**。创建虚拟机时不用从零装系统——从镜像"复印"一份启动即可。平台支持两种玩法：

- **云镜像**：从官方源下载的精简系统盘（Rocky/Ubuntu 官方版），配合 cloud-init 首次开机自动注入账号密码，**几十秒出机**
- **增量克隆**：基于已有虚拟机的磁盘"引用"创建新机，**不复制数据**，初始只占几 MB

> 类比：镜像 = 房间的**样板间图纸**。增量克隆连图纸都不复印，直接指着原件看。

## 存储池（Storage Pool）

**虚拟机磁盘文件的存放目录**。比如 `/var/lib/libvirt/images`。每台虚拟机的磁盘是池里的一个 `.qcow2` 文件。平台里可以建多个池——系统和数据分开放。

> 类比：存放所有房间的**家具仓库**。

## 虚拟网络（Network）

虚拟机之间、虚拟机与外网通信的"虚拟交换机"。默认的 NAT 网络让每台虚拟机自动拿一个内网 IP 并能访问外网。

> 类比：楼里的**水电管线**——建房时自动接好。

## 快照（Snapshot）

**虚拟机在某一瞬间的"存档点"**。做危险实验前拍一个，搞坏了 30 秒回滚到拍照时刻。利用的是 qcow2 磁盘的链式能力。

> 类比：游戏**存档**。打 Boss 前先存一下。

## SSH 跳板（Jump Server）

不打开浏览器也能连虚拟机的入口：`ssh 用户名@服务器IP -p 2222`，登录后平台给你一份**只属于你的机器菜单**，选编号直达。这是堡垒机（如 JumpServer）的经典形态，本项目已内置。

> 类比：楼门口的**智能前台**——刷你的卡（账号），只带你能进的房间。

## 概念 ↔ 菜单对照表

| 概念 | 平台菜单 | 你能做什么 |
|---|---|---|
| 宿主机 | 基础设施 → 宿主机 | 看 CPU/内存水位、测连通性 |
| 虚拟机 | 资源 → 虚拟机 | 创建/开关机/快照/控制台 |
| 镜像 | 资源 → 镜像管理 | 上传 ISO、下载云镜像、做模板 |
| 存储池 | 基础设施 → 存储池 | 建池、看容量、管磁盘文件 |
| 虚拟网络 | 基础设施 → 网络 | 建 NAT/隔离网络、开关自启 |
| 快照 | 虚拟机详情 → 快照 | 拍照/回滚/删除 |
| SSH 跳板 | 终端直接 `ssh -p 2222` | 任意终端工具直连资产 |
