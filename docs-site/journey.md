# 从 0 到 1 构建之旅

这一章不是使用说明，而是**这个项目是怎么一步步长成现在这样的**——每个关键决策背后都有一段真实的故事（和事故）。适合答辩前通读，也适合想理解"为什么是这么设计的"的同学。

## 起点：一句话需求

> 实验室里学生要用虚拟机，以前的流程是：找老师要 root 密码 → SSH 上宿主机 → 敲 `virt-install` → 密码在群里传来传去。

四个痛点：**明文密码满天飞、libvirt 权限全有或全无、没有浏览器控制台、没有任何审计**。这就是项目的全部出发点。

## 里程碑一：先把「创建虚拟机」变成三次点击

最初的原型只有一件事：把 `virt-install` 的命令行参数变成一个四步向导。背后踩的第一个大坑是 libvirt 的连接方式——最终选定 `digitalocean/go-libvirt` 走 unix socket 直连 `qemu:///system`，纯 Go 无 CGO，编译出来就是单二进制。所有 libvirt 调用收敛进 `service/virt` 封装层，错误统一 `%w` 中文包装——这条规范后来救了无数次排障。

## 里程碑二：增量克隆——一次「名不副实」的返工

实现「批量做实验机」时最初用了 `StorageVolCreateXMLFrom`（等价 `virsh vol-clone`），看起来能用。但实测发现它做的是**全量数据拷贝**：30 个学生的实验机 = 30 份完整磁盘。正确的做法是 qcow2 的 `<backingStore>`（ backing file 链）：子盘只存与父盘的差异，初始占用近零。

教训固化成了一条验收标准：**功能语义用外部工具反证，不用代码注释自证**——`qemu-img info` 必须看到 `backing file:`、`virsh vol-dumpxml` 必须有 `<backingStore>`。这条后来在删除保护（父盘被删则子链全毁 → 删卷三重守卫）上再次发挥作用。

## 里程碑三：安全不是功能，是「编译期做不到」

项目经历过一次最深刻的教训：新增应用安装模块时**漏调了一行 SSH 白名单校验**——平台瞬间变成免费跳板机（可以驱动服务器 SSH 内网任意主机），而代码看起来完全正常、测试全绿。

治本方案不是「记得调用」，而是把 `vmssh.Options` 的字段全部改成不可导出，**包外无法构造**、唯一入口构造函数内部强制白名单校验。「绕过白名单」从「靠人记得」变成「编译期做不到」。同批次还建立了**列名护栏测试**（GORM 字段名与列名不一致的 1054 错误曾两次静默吞掉写库）和 **`dbx` 写库收口**（`_ =` 丢错导致僵尸任务的教训）。

## 里程碑四：审计与 4A——从「记录」到「闭环」

- RBAC 三级角色（admin/operator/viewer）+ 资产授权（授权决定可见性：未授权用户**查无此项**，而不是 403——连「有这台机器但不给你看」都不泄露）
- 会话审计（vnc/ssh/serial）+ 操作日志
- 后来加入的 SSH 跳板（jumpd）把 4A 从 Web 延伸到任意终端：**授权决定菜单可见性、连接前现查重验、目标只能来自选单**（注入面天然消失）

## 里程碑五：教学场景特化（4A 闭环）

用户组授权、申请审批流、命令黑名单三件套，让「教师一句话的口头需求」变成三条点击：

> 学生自助申请 → 教师审批限时授权 → 组授权批量生效 → 任意终端直连 → 危险命令拦截 → 全程审计。

实现中的坑各有代表性：申请入口**不能走可见性检查**（申请者的定义就是没授权，查了必 404 死锁）；Vue 的 `close-on-click-modal="false"` 静态 attribute 传的是字符串 truthy（必须 v-bind）；跳板桥接的用户通道**只允许一个读者**（两个读者抢字节流 = 菜单乱跳）。

## 工程方法沉淀

1. **并行子代理派发**：文件域严格互斥、各自独立验证、主控做并集联合冒烟
2. **脚本化编辑三纪律**：完整函数体锚点 + assert + 落盘后立即验证
3. **构建通过 ≠ 运行正常**：浏览器真机冒烟是每个批次的收口动作
4. **行为基线先行**：重构必须从「已知良好状态」开始，否则拆坏了分不清是谁的锅
